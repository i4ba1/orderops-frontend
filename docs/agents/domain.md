# Domain documentation

## Read before exploring

Use the single-context layout: root `CONTEXT.md` and `docs/adr/`.

Read `CONTEXT.md` and ADRs relevant to the task. If a root `CONTEXT-MAP.md` exists in the future, follow its relevant context pointers instead.

If domain files are absent, proceed silently. Domain modeling creates them when terminology or decisions are resolved.

## Vocabulary and decisions

Use terms defined in `CONTEXT.md` in tickets, tests, and design proposals. Raise meaningful terminology gaps during domain modeling.

When proposing a change that contradicts an ADR, identify that ADR and explain why the decision should be reconsidered.
